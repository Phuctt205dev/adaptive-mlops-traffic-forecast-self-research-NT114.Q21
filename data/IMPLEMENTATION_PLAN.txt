================================================================================
I. TỔNG QUAN DỰ ÁN
================================================================================

Bối Cảnh:
  Các hệ thống dự báo lưu lượng giao thông thường gặp vấn đề khi dữ liệu
  trong thực tế thay đổi so với dữ liệu training, dẫn đến hiệu năng model
  giảm. Việc phát hiện và xử lý những thay đổi này (drift) thường phải
  thực hiện thủ công.

Mục Tiêu Chính:
  Xây dựng một quy trình MLOps hoàn chỉnh có khả năng:
  - Tự động phát hiện khi model không còn hiệu quả (data drift detection)
  - Tự động retrain model khi cần
  - Lựa chọn model tốt nhất từ nhiều ứng cử viên
  - Duy trì và theo dõi hiệu năng model liên tục

Đối Tượng Sử Dụng:
  Hệ thống được thiết kế cho nhóm data engineers, ML engineers, và operations
  teams cần quản lý model machine learning trong thực tế.

IV. GIAI ĐOẠN 2: PHÁT TRIỂN MODULE PREPROCESSING
================================================================================

Mục Đích: Xây dựng bộ xử lý dữ liệu linh hoạt, có thể tái sử dụng.

Các Công Việc:

  4.1 Data Loading:
    - Viết hàm load_data() đọc từ CSV
    - Kiểm tra encoding, delimiter
    - Validate dữ liệu ban đầu
    - Handle errors, logging

  4.2 Feature Engineering:
    - Extract time features từ datetime column (hour, day, month)
    - Tạo cyclical features cho time (sin/cos encoding)
    - Tạo binary features (is_weekend, is_holiday)
    - Encode categorical features (weather_type → one-hot)
    - Scale/normalize numerical features

  4.3 Data Cleaning:
    - Handle missing values (drop, imputation)
    - Remove outliers nếu cần
    - Validate feature ranges
    - Check data consistency

  4.4 Data Splitting:
    - Implement time-based split (không random shuffle vì time series)
    - Train set: 70% toàn bộ data
    - Validation set: từ phần còn lại
    - Tùy chọn test set

  4.5 Deliverables:
    - src/preprocess.py với các hàm:
      * load_data(path)
      * preprocess(df)
      * split_data(df)
    - Tài liệu về features được tạo
    - Test cases cho preprocessing

================================================================================
VI. GIAI ĐOẠN 4: PHÁT TRIỂN MODULE DRIFT DETECTION
================================================================================

Mục Đích: Xây dựng khả năng phát hiện khi model cần retrain.

Các Công Việc:

  6.1 Triển Khai Hàm Drift Detection:
    - detect_drift_by_mae(y_true, y_pred, threshold)
    - Tính Mean Absolute Error
    - So sánh với threshold có định
    - Trả về: (drift_detected: bool, mae_value: float)

  6.2 Cơ Chế Phát Hiện:
    - Phương pháp: MAE-based (simple, effective)
    - Threshold mặc định: 500 (tùy chỉnh được)
    - Quy tắc: MAE > threshold → Drift = True
    - Logging: In ra MAE, threshold, decision

  6.3 Tích Hợp Vào Workflow:
    - Sau mỗi prediction, gọi detect_drift()
    - Lưu kết quả drift detection
    - Prepare trigger cho retrain

  6.4 Deliverables:
    - src/drift.py với detect_drift_by_mae()
    - Hướng dẫn cấu hình threshold
    - Test cases cho drift detection

Timeline: 2-3 ngày

VII. GIAI ĐOẠN 5: TRIỂN KHAI HỆ THỐNG ORCHESTRATION
================================================================================

Mục Đích: Kết nối tất cả modules thành 1 hệ thống hoàn chỉnh.

Các Công Việc:

  7.1 Triển Khai Main Orchestrator (main.py):
    - Khởi động hệ thống
    - Kiểm tra model có tồn tại?
      * Nếu không: Training initial model
      * Nếu có: Tiếp tục
    - Load data, preprocess
    - Load model
    - Predict trên dữ liệu mới
    - Detect drift
    - [Nếu drift] Trigger retrain
    - [Nếu không] Keep current model

  7.2 Cấu Hình Tham Số Chính:
    - TRAIN_START_DATE, TRAIN_END_DATE (initial training window)
    - PREDICT_START, PREDICT_END (inference window)
    - MAE_THRESHOLD (drift detection threshold)
    - MODEL_PATH (nơi lưu model)

  7.3 Workflow Chi Tiết:
    Step 1: Check model existence
    Step 2: Load/Create model
    Step 3: Load & preprocess data
    Step 4: Get new data window
    Step 5: Make predictions
    Step 6: Calculate metrics
    Step 7: Detect drift
    Step 8: Make retrain decision
    Step 9: Log results

  7.4 Logging & Monitoring:
    - In ra quá trình chi tiết (Training, Predicting, Drift Check)
    - Lưu logs vào file (optional)
    - Track: timestamp, metric values, decisions

  7.5 Deliverables:
    - main.py file
    - Configuration file (config.yaml hoặc hardcoded constants)
    - Logging setup
    - Usage documentation

Timeline: 3-4 ngày

================================================================================
XVI. RISKS & MITIGATION
================================================================================

Risk 1: Data Quality Issues
  Mitigation: Implement comprehensive data validation, early data exploration

Risk 2: Model Overfitting
  Mitigation: Use cross-validation, hold-out test set, regularization

Risk 3: Drift Threshold Too Sensitive
  Mitigation: Start conservative, tune based on historical data

Risk 4: Retrain Takes Too Long
  Mitigation: Optimize training, consider incremental learning

Risk 5: Model Performance Regression
  Mitigation: Keep previous best model, A/B test before rollout

Risk 6: Production Failures
  Mitigation: Comprehensive testing, graceful error handling, logging

================================================================================
XVII. NOTES & BEST PRACTICES
================================================================================

- Luôn sử dụng time-based splitting cho time series data, không random
- Lưu model metadata (training date, hyperparams, metrics) cùng model
- Implement logging từ sớm để dễ debug sau
- Validate mọi input/output, không assume dữ liệu sạch
- Use random state để đảm bảo reproducibility
- Test code thường xuyên, không để tới cuối
- Document assumptions, hạn chế, cách sử dụng
- Keep it simple, không over-engineer sớm
- Use version control, commit frequently with clear messages
